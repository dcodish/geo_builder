    Modelling choices

    • One pool per kind of instance, not per agent. A round fixes many bugs and a scan finds many, and one pool cannot hold two instance counts. The three system pools sit in one group, «Geo Builder dev system».
    • The operator is a white-box pool: the workflow prescribes his steps (play, rule, start a round, approve).
    • The production server is a black box: only the deploy and the smoke-test result cross its border.
    • The prod-log scan has a timer start, as the operator is about to schedule it. Today it runs on request.
    • Today the scan files its bug clusters itself. The diagram shows them entering the same triage as every other report.
    • GitHub Issues is the shared data store; its labels (reported, auto-ok, in-round, awaiting-play) are each bug's state.
