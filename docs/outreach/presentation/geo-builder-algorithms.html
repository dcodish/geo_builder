The idea · 02

Why a dependency-graph engine — and what falls out of it

The dead end

A shape-template matcher recognises whole figures ("this is a square"). It cannot represent a free point, a point sliding on an object, accumulating constraints, or alternative configurations — so incremental building is impossible.

The move

Every object is defined in terms of earlier objects and classified by its degrees of freedom. A figure is a dependency DAG evaluated in topological order into coordinates.

Two headline behaviours are not features we bolted on — they are consequences of the representation:

Alternatives. An intersection has 0/1/2 solutions; a branch index picks one; "show another" enumerates the next — model enumeration, for free.

Stability. DOF parameters and branch indices persist across steps, so adding a constraint re-evaluates downstream objects without perturbing earlier choices — the figure never jumps.

Over-constraint is general. If a step can't be satisfied, flag it, keep the prior figure, and explain — no per-shape special cases.

Two counts, one truth. Raw DOF counts every movable parameter. Shape DOF quotients out the similarity gauge — the 4 free choices of placement (2 translate + 1 rotate + 1 scale) that don't change the shape.

That's why the figure ends at raw 4 = the gauge, i.e. shape DOF 0: rigid up to where you put it and how big it is. This is exactly when the UI reports "✓ fully determined".

No fixed assumptions. Every unstated magnitude stays a free DOF — never a silent default. "Show another configuration" resamples them; a later given may pin them.

Algorithm 1 · 06

Evaluate — topological order with an interleaved fixed-point sweep

  1. function Evaluate(commands) → positions
  2. G ← buildDependencyGraph(commands) # points, lines, circles, constraints
  3. order ← topologicalSort(G) # parents before children
  4. positions ← { }
  5. repeat # interleaved fixed point
  6. changed ← false
  7. for node in order:
  8. if node is Circle or Line: resolve(node)
  9. elif node is DerivedPoint: positions[node] ←
  10. f(parents, branchIndex[node]) # the 0/1/2-solution pick
  11. elif node is Constraint: DriveOrCheck(node)
  12. changed ← changed or updated(node)
  13. until not changed or iters > MAX
  14. if unresolved: flag(OVER-CONSTRAINED / COINCIDENT)
  15. return positions

Why a fixed point, not one pass?

A line can depend on a point that depends on a circle that depends on that line's anchor. One topological pass isn't enough when object kinds interleave, so the sweep repeats until stable — circles, lines, and points resolve together.

Deterministic & pure

No template matching, no previousPositions threading. Given the same graph it always yields the same coordinates — the engine is the single source of truth and is tested hardest.

Failure is first-class

If the sweep can't settle, it flags over-constraint / coincidence rather than drawing a wrong figure — general, not per-shape.

Algorithm 2 · 07

DriveOrCheck — the solver inside the interpreter

  1. function DriveOrCheck(constraint c)
  2. refs ← referencedPoints(c)
  3. free ← recruitFreeDofs(refs) # walk ancestors:
  4. # free params, radii, centres, branch DOFs —
  5. # keep walking PAST a free on-object carrier
  7. if free = ∅: # everything determined
  8. r ← residual(c, positions)
  9. if |r| > ε:
  10. markOverConstrained(); keep prior; explain()
  11. # else: satisfied — a pure check
  12. else: # a DOF to drive
  13. roots ← solveParam(free, residual(c) = 0)
  14. branchIndex[c] ← clamp(branchIndex[c], roots)
  15. apply(roots[branchIndex[c]]) # chosen alternative

Drive vs. check — one rule

If any referenced point still owns a free DOF, the constraint solves for it. If not, the same constraint becomes a check. One mechanism, no imperative special cases.

solveParam

A deterministic 1-D root finder. Multiple roots become alternatives (the branch index selects one). Adding a constraint is "just" a new solver case: a residual + refs + a description.

Recruiting the right DOF

The ancestor walk keeps going past a free on-object carrier to reach the shape DOF behind it — so a perpendicularity given can flex a rhombus's angle, not just slide a point onto its neighbour.

Algorithm 3 · 08

Show-another-configuration — enumerating the space of valid drawings

  1. function ShowAnother(figure)
  2. # output is one model from a space of models
  3. if hasNextBranch(figure):
  4. branchIndex ← branchIndex + 1 # next ∩ solution
  5. else:
  6. seed ← nextSeed() # reproducible
  7. resample(freeDofs, seed) # sizes, t, radius,
  8. # centre — continuous
  9. applyReflections(seed.highBits) # discrete mirror DOFs
  11. reevaluate(figure)
  12. keep only configs where meetsRequirements(figure)
  13. # e.g. a meet must land ON the segments,
  14. # an extension must reach the far side

Two axes of variety

Branches enumerate the finite 0/1/2 intersection solutions. Sampling varies the continuous free DOFs. Together they walk the whole valid space.

Reflection DOFs

Some choices are discrete but unstated — which side a triangle's apex falls on. Encoded in the seed's high bits so the sampler can mirror into configurations a continuous nudge would almost never reach.

Seeded & filtered

Every configuration is reproducible from its seed, and only those that satisfy the stated requirements are shown — the same predicate the verifier uses.

Algorithm 4 · 09

Replay with deferral — order-independent, event-sourced rebuild

  1. function Replay(facts) → figure
  2. positions ← ∅ ; pending ← ∅
  3. for fact in enabledFacts: # fact list = program
  4. try applyStep(fact)
  5. catch pending.add(fact) # keep prior on error
  7. repeat # deferral to a fixpoint
  8. for fact in pending:
  9. if applyStep(fact) succeeds now:
  10. pending.remove(fact)
  11. until no change
  13. # a constraint typed BEFORE its givens
  14. # auto-defers until they arrive

Positions are derived, never stored

The ordered fact list is the single source of truth; the figure is replayed from it. Undo = recompile a prefix. State and coordinates cannot desync.

Order independence, for free

Type CE ⟂ AB before the sizes that pin it, and the deferral loop retries it once the determining givens land. The full figure builds in any entry order.

The honest limit

A genuinely under-determined partial figure stays pending until its determining givens arrive — which is correct, not a bug.
