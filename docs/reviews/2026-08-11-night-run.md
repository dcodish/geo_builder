## 1 · A parametric line's running parameter is YOUR letter — #422, ADR-3D-129 (on `main`)

You reported `l1:x=(4,5,-1)+m(k, 1,0)` as not understood while the same line with `t` built fine. A
parametric line carries two letters in two roles: the one **outside** the parens is a bound variable you
pick, the one **inside** a component is a figure DOF the givens later pin. The grammar had fixed the
bound one at `t`, so the identical geometry with the letters swapped had no rule.

**Type this:**

```
l1:x=(4,5,-1)+m(k, 1,0)
```

Expect: it builds, `k` stays a free sampled DOF, and the canvas echo reads `ℓ1: x = (4,5,-1) + m·(k, 1, 0)`
— **your letter, not `t`**. Both echo sites used to rewrite it back.

**Controls — must be unchanged:**

```
l1:x=(4,5,-1)+t(k, 1,0)
הישר ℓ: x = (-1,5,-11) + t(m-1, 5-m, -2)
```

**Must still REFUSE:**

```
l1:x=m(m-1, 5-m, -2)
```

One letter in both roles conflates a bound variable with a figure DOF; which you meant is not ours to
guess, so it escalates rather than building on an assumption.

**Left open for you:** should a **Greek** running parameter (`λ`, used in some textbooks) parse too? Greek
letters currently mean something else here — the point-in-span lane's unknown scalars — so that needs a
ruling, not a regex.

### #509 / #504 — nonlinear and symbolic components

`C(p^2,p^2+4,0)` refuses because the symbolic coordinate model is affine by construction — a component
*is* `k·sym + c`, and degree 2 has nowhere to live. The issue asks you to pick a carrier before any code.

My independent read, posted to the issue: **I agree with option B** (a small numeric scalar-expression
tree). The six failing forms are not variations of one shape — they are six directions of pressure on the
same wall: degree, products, two symbols in one component, division, parenthesisation, and literals.
Option A answers one. The sixth (literals) shipped last night as #510, so five remain.

Three things to decide:

1. **A / B / C** — I recommend B.
2. **Branch semantics.** With `p²`, a pinned value admits `p = ±√·`, so the roots are branches. Reusing the
   existing "show another configuration" machinery is right, but a figure then gains branches the student
   never asked about — surfaced or silent is a pedagogy call.
3. **Where the no-CAS line sits.** My reading: the tree is *evaluated*, never rearranged; solving
   symbolically for `p` would cross it. Worth confirming — that constraint is what keeps option B small.

#504 sits on the same carrier and should be built in the same slice, not alone.
