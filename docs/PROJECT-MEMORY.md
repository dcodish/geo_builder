Discussed + recorded as a Proposed ADR with the naive form rejected and the sound form chosen. **Naive (rejected):** LLM returns coordinates → LLMs are worst at numerical constraint-satisfaction (plausible-but-wrong numbers), and it risks the cardinal sin — drawing a figure that doesn't satisfy the givens; also the engine is deterministic code, not a learned model (no runtime "teaching"). **Sound (decided):** LLM owns *structure* (a re-decomposition into primitives the engine solves exactly) or a *seed* (rough layout / branch / which DOF to drive), the engine owns *arithmetic + verification* — every LLM output passes the `isSatisfied`/residual gate before anything draws (reject → keep-prior). Contradictions are flagged, never "solved." The "learning" is **offline + supervised**: auto-harvest each LLM/seed success-where-engine-failed into a corpus/regression fixture + a "missing construct / weak basin" queue (the existing debug-log→scenario rule, automated). **Sequencing:** depends on the ADR-045 solver/seeding consolidation + the production proxy deploy (parked); not before. Highest-value variant = LLM-as-seed (most non-contradiction failures are basin/far-branch failures, per the audit). No code.
