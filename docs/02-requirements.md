# 02 — Functional Requirements

_Scope: v1 ("broader v1" — see [Design §Scope](04-design.md))._

## How this document is organised

Each requirement is one promise: **`FR-<area>-<n> (Tier)`**, the promise sentence, the few clauses that are still
part of it, at most three examples, any ⚠ marker, and a **Sources** line naming the ADRs and issues that hold its
history and rationale. Requirements are grouped by what a student meets — input (read · asked · refused),
refusals and honesty, the figure and its marks, configurations, knowledge, session, language — so an id's area
prefix records where it was first filed, not the section it sits in. The ADR log ([06](06-decisions.md)) is the
history; this file is the current promise.

IDs are stable references (`FR-<area>-<n>`). "Must" = v1; "Should" = desirable in v1; "Later" = post-v1; "Withdrawn" = no longer in THIS product's scope, with the reason and the new owner stated.

**A tier is a claim about reality and is audited against the code** ([ADR-W-041](06w-decisions-workspace.md#adr-w-041)). A tier left stale is not cosmetic: a session planning from it builds the wrong thing.

## Actors

- **Student** — describes a figure step by step to understand a problem.
- **Teacher** — same capability; prepares or demonstrates figures, and authors materials.
- **Author** — a teacher or textbook author who builds figures to embed in exams, worksheets, or books; primary need is image export.
- (No authentication or distinct roles in v1; all are the same anonymous user.)

## User stories

### Student

- US-1 — As a student, I want to enter the problem's facts one at a time and see the figure update after each, so that I understand how each given shapes it.
- US-2 — As a student, I want to choose among the valid drawings when my figure isn't fully determined, so that it matches the problem I'm solving.
- US-3 — As a student, I want to be told clearly when a fact conflicts with earlier ones, so that I can correct my input instead of trusting a wrong figure.
- US-4 — As a student, I want to see the theorems relevant to the figure I've built, so that I understand why the data was given and how to approach the solution.
- US-5 — As a student, I want to undo and redo steps, so that I can fix a mistake without rebuilding from scratch.
- US-6 — As a student, I want to clear the figure and start over, so that I can move on to a new problem.
- US-7 — As a student, I want a clear hint on how to phrase a fact when it isn't understood, so that I can continue without getting stuck.
- US-8 — As a student, I want to see the list of facts I've entered, so that I can track what the figure is based on.
- US-9 — As a student, I want to drag a point that isn't fully fixed, so that I can explore how the figure is free to vary.
- US-10 — As a student, I want my figure to still be there after a reload, so that I don't lose my work.

### Teacher

- US-11 — As a teacher, I want to build a figure live in Hebrew with no setup, so that I can demonstrate a problem to my class.
- US-14 — As a teacher (or student), I want to **save a completed figure to a file and load it back later**, so that I (and my students) can reuse a diagram instead of recreating the same construction over and over.

### Author

- US-12 — As an author, I want to describe a figure and export it as a clean image, so that I can include accurate diagrams in exams, worksheets, and books without drawing them by hand.

### All users

- US-13 — As a user, I want to work in Hebrew or switch to English, so that I can use the language I'm comfortable with.

## Input & parsing

### What is read

- **FR-IN-1 (Must)** — Accept free-text input in Hebrew and English describing geometry facts.
- **FR-IN-2 (Must)** — Translate each accepted input into one or more structured commands the engine can apply. (How — local parser first, LLM fallback — is a design decision; see [ADR-002](06-decisions.md).)
- **FR-IN-3 (Must)** — Each submitted utterance is one **step**: it may produce several commands (e.g. "square ABCD" creates the polygon plus its right-angle/equal-side constraints).
- **FR-IN-5 (Should)** — Offer input affordances (examples, autocomplete, or a guided builder) so users phrase facts the parser supports.
- **FR-IN-6 (Should)** — Accept **relational measures with named variables** that set a relation between measures *without fixing a number* (the tool draws the relation; the student solves for the unknown): a length as `coef·var` with a lowercase-latin variable (`AB = 3x`) and an angle as `coef·var` with a Greek variable (`∠ABC = 2α`); points stay uppercase so the two never collide. Measures sharing a variable form a proportion (`AB = 3x` + `DF = x`), and a value for it (`x = 4`) resolves them all; the figure stays free until something pins the scale. Any copula that states a numeric value states a symbolic one; a symbolic value the tool cannot read is **refused or escalated, never valued at its coefficient**; a Hebrew particle's maqaf («שווה ל-90») is never a minus sign. Two **angles** relate through any copula; two **arcs** only through «קשת CD שווה לקשת DE» — the copula form is refused, teaching that sentence.
  - Sources: ADR-031, ADR-498, ADR-505, ADR-507, ADR-533, ADR-W-030.
- **FR-IN-7 (Should)** — A **relation or measure stated over named segments/angles** also **draws** the segment(s) it names, so stating a fact puts its lines on the figure without a separate "draw segment" request: a line relation (`AB ⟂ CD`, `AB ∥ CD`) draws both segments; a length given (`AB = 6`) draws `AB`; an equality (`AB = CD`) draws both compared segments; an angle (`∠ABC = 37`) draws its two arms (`BA`, `BC`). Drawing is idempotent; symbolic measures do not yet auto-draw. A length with its **role** in front («האלכסון AC = 8») draws the role and fixes the length. A height given as a number with no segment («גובה הטרפז 4») builds for a trapezoid and ASKS which height for a parallelogram or a triangle; a height or median that names its side or vertex («הגובה לצלע BC הוא 4») keeps its number. A crossing sentence draws its grammatical **subject**: «AC ו-BD נפגשים בנקודה M» draws the lines with M; «M מפגש AC ו-BD» draws M alone.
  - Sources: ADR-574, #1607, ADR-575, #1443, ADR-592, #1751.
- **FR-IN-7b (Should)** — Accept an **angle ACUTENESS** assumption — `∠ABC קהה` (obtuse, >90°) / `∠ABC חדה` (acute, <90°), including the single-vertex form `∠C` (arms inferred from the figure) — and **actively reshape** the figure so the angle falls on the requested side (a one-sided constraint that removes no DOF; the same class as FR-IN-8).
  - Sources: ADR-108.
- **FR-IN-7c (Should)** — An angle may be named by the **two sides that form it**, not only by its three letters: «הזווית בין BD ל-BA היא 30» / "the angle between BD and BA is 30" states the same given as «זווית DBA = 30», because the two named segments share the endpoint B. It is an addressing mode, accepted wherever an angle is named (FR-IN-6, FR-IN-7b, FR-IN-8) and drawing its arms. Two segments with no shared endpoint are **refused by name**, never bound to a guessed vertex or escalated.
  - Sources: ADR-052, ADR-496, #967; 3-D counterpart #534/#523/#917.
- **FR-IN-7d (Should)** — An angle may be named by its **vertex alone** — «זווית B = 30», «B = 30», «∠B = 2∠C», «זווית B חדה», «BE חוצה זווית B» — wherever an angle is named. With two edges at the vertex it is the angle between them; with more, and **exactly one declared polygon** there, it is that polygon's interior angle and the step says so («הובן כ-∠ABC»); otherwise the tool **asks which**, listing every candidate («∠ABC, ∠ABD, ∠CBD»), and the example it teaches builds. The analytic Builder reads it the same way.
  - Sources: ADR-590, #1445, ADR-164 (partially superseded), ADR-W-108.
- **FR-IN-7d (Must) — a trigonometric given is a ratio.** «tan∢ABC = 2», «tan(∢ABC) = 2», «tg∢ABC = 2», «tan B = 2», «טנגנס הזווית ABC הוא 2», «cot∢ABC = 2», «cos∢ACB = 3/4», «קוסינוס הזווית ACB = 3/4», "the cosine of angle ABC is 0.5" each state the ONE angle in (0°, 180°) with that tangent / cotangent / cosine — a negative tangent or cosine is an obtuse angle — and the figure labels the **angle** it draws, rounded like every displayed number («tan∢ABC = 2» → «63.43°»), never the ratio «tan=2»; the fact row keeps the sentence as typed ([ADR-572](06-decisions.md#adr-572), #1718, amending ADR-566's «tan=2» label). Any concrete value is accepted (a fraction, a decimal, «√3»). A **sine** in (0, 1) builds as a configuration choice between θ and 180° − θ (acute by default; the other givens may force one); sin = 1 is 90°. A trig statement that names no angle — a sine outside (0, 1], a cosine outside [−1, 1], a comparison, a symbol, a clause — is **refused by name, never drawn or escalated**, with a note teaching the readable form. «∢ABC = 90/2» is one value.
  - Sources: ADR-566, #1698, ADR-573, #1711; analytic sibling ADR-AG-215.
- **FR-IN-8 (Should)** — Accept an **ordering assumption between two named measures** (`α < β`, `x > y`, also `≤`/`≥`) and **actively reshape** the figure so the relation holds *visibly* — the angle (or segment) labelled with the smaller variable comes out clearly smaller — while every other given still holds. An ordering selects a configuration; it never fixes a number. If the geometry permits only a small gap the figure still adopts it; if it is incompatible with the other givens, the prior figure is kept and the contradiction is flagged.
  - Sources: ADR-039.
- **FR-IN-10 (Should) — the student never orders the construction.** A student transcribes a problem in the order it is *written*, which is often the reverse of the order a topological engine can *build* it (a late-introduced organising object, an implicit/unstated object, coupled givens). The tool reorders and makes implicit objects explicit so the figure forms without the student planning ahead: a given not yet satisfiable is deferred and retried, and a row above the rows declaring its points builds once they exist (a row whose points nothing declares stays red, naming them). **Not built** (ADR-073 is design-only, #1861): LLM reordering with a repair loop, and whole-problem paste. A stated given is **never** dropped or weakened to force a result; contradictory or under-/over-specified input is reported honestly, the figure kept.
  - Sources: ADR-104, ADR-577, ADR-073; distinct from the solver rescue ADR-049.
- **FR-IN-11 (Should) — the student never names the construct.** An unnamed construct request — «אמצע AB» / "midpoint of AB", «משיק למעגל» / "a tangent to the circle", «קוטר» / "a diameter", «ישר החותך את המעגל בשתי נקודות», «נתון מעגל», «מרכז המעגל» — builds with **auto-chosen labels** (the `freeLabel` discipline the median/altitude rules established: every existing label excluded), optionally wrapped in a request verb («הוסף/להוסיף», "add/draw"). The unnamed rules are strict last-resorts.
  - Sources: ADR-368, #184.
- **FR-IN-12 (Must) — «המעגל» means the circle that is already drawn.** A statement about *the* circle — «המעגל עובר דרך A [ו-B]» (also «דרך הנקודה A», «עובר בנקודה A»), "the circle passes through A", or the named «מעגל O עובר דרך A» over a drawn O — is a statement ABOUT that circle: every point it names is put on it, exactly as «A [ו-B] על המעגל» does, and a size stated alongside («… ברדיוס 3») applies to the same circle. It never draws a second circle or drops a listed point; beside several circles it asks which; with none drawn the words introduce one; a definition names every point it passes through. A tangency («AB ו-BC משיקים למעגל בנקודות A ו-C בהתאמה») binds the same way. Putting drawn points on a circle of unstated size or place moves the circle, not the figure (three vertices of a triangle make its circumcircle).
  - Sources: ADR-548, #1438, ADR-560, #1650, #1619, ADR-576, #1471.
- **FR-IN-13 (Must) — a piece named by its role keeps its role.** When a sentence names a segment by what it is — «המיתר BC», «הקוטר BC», «הרדיוס OB», «היתר AB», «השוק AB», «הבסיס AB» (and "the chord / diameter / radius / hypotenuse / leg / base") — inside any other given («… מקביל ל-AD», «… = 5», «E על …», «… חותך את …»), the role is honoured, not just the segment: a chord's ends are on the circle, a diameter also passes through the centre, a radius runs from the centre to the circle, the angle opposite a hypotenuse is right, an isosceles base makes the opposite vertex the apex, a trapezoid's leg or base fixes which sides are parallel. Only the pair the noun is attached to gets the role. A role that cannot hold (a chord through the centre, a hypotenuse of no triangle) is refused naming the sentence, never drawn as a plain segment.
  - Sources: ADR-563, #1661; analytic sibling ADR-AG-200.
- **FR-IN-4d (Must) — a point placement keeps its tail.** A sentence that places a point («הנקודה E נמצאת על המשך הצלע BC», «D על BC») and then says more keeps all of it: a condition clause — «כך ש», «ונתון כי / ונתון ש / וידוע כי», "and it is given that" — is a given held on the figure, and «מעבר לנקודה B» / "beyond B" picks the end of the segment the extension passes. A tail the tool cannot read is escalated or refused, never dropped from a green figure. A shape with a given glued on («משולש ABC ונתון כי AB = AC») stays the two-step teaching.
  - Sources: ADR-570, #1682, #108.

### What is asked or taught

- **FR-IN-4 (Must)** — When input cannot be understood, show a helpful clarification message (bilingual) and leave the figure unchanged. A sentence the tool understood but which misses a given **asks** for it, keeping the text in place («מלבן ABCD שהצלע שלו 6» names no particular side).
  - Sources: ADR-052, ADR-494, #957.
- **FR-IN-9 (Must)** — **An under-specified statement is ASKED about, never guessed and never escalated.** When an utterance names a relation but leaves an operand genuinely absent — «צלע AD גדולה פי 2» (twice *what*?) — the tool answers with a clarification naming what is missing and keeps the student's text so they can complete it in place. A cevian whose triangle is ambiguous («AE גובה» where A has several opposite sides) asks which; a bisector's stated vertex («AD חוצה זווית C») is honoured or refused, never replaced.
  - Sources: ADR-052, ADR-490, #777, #775, ADR-568, #1684.
- **FR-IN-4b (Should)** — **A label-convention mismatch is TAUGHT, not met with silence.** Vertices are named with uppercase Latin letters. Lowercase (`abcd`) or **Hebrew-alphabet** labels (`מלבן אבגד`) get the corrected sentence (`מלבן ABCD`) as a note, commit nothing, and keep the text — only when the corrected sentence parses, and before any LLM call. Hebrew-letter labels are rejected with the notice, not supported (operator ruling).
  - Sources: ADR-497, #968, #779.
- **FR-IN-4e (Should)** — **A word fraction or a wish is TAUGHT as the given it means.** A length given written with a **word fraction** («רבע», «שלושה רבעים», «שני שלישים», "a quarter of") or wrapped in a **wish or a command** («אני רוצה ש-BE ו-DF יהיו רבע מהצלע של המקבילית», «הפוך את BE ואת DF להיות 3/4 מצלע המקבילית», "I want BE to be …") is **not accepted as input** (operator ruling, 2026-09-30). The tool answers with the canonical sentence meant («BE = 1/4 BC, DF = 1/4 AD»), pre-filled in the input and committing nothing — only when that sentence itself builds, and before any LLM call. A fraction with no comparand is never completed by a guess.
  - Sources: ADR-591, #1611.

### What is refused

- **FR-IN-4c (Must)** — **A ROLE NOUN is a claim about the figure, and the tool stands behind it.** Words that assign a role — «אלכסון»/"diagonal" today, and the family it belongs to — do not merely point at an object, they assert something about it, and the tool never accepts one it can show to be false. «אלכסון AB» where AB is a side, or on a triangle, is refused by name, never drawn or answered "already drawn"; a claim the figure cannot yet judge is checked against the finished figure. Named lines are never replaced by other lines.
  - e.g. «מרובע ABCD» · «האלכסונים AB ו-CD נפגשים» → refused, naming the side
  - e.g. «התיכונים AD ו-BE נפגשים בנקודה G» → AD and BE are medians
  - Sources: ADR-499, #966, #859, ADR-569, #1683.
- **FR-IN-9 (Withdrawn) — coordinate data-entry mode (analytic geometry).** A future, *opt-in* input mode where the student places points/objects by explicit **coordinates** (`A = (3, 4)`) and builds on a coordinate grid — useful for **analytic ("analytical") geometry**, where the coordinate system is the point of the exercise. **Withdrawn from 2-D:** analytic geometry is the analytic Builder (`src-analytic/`, [02c](02c-requirements-analytic.md)). Coordinates in any spelling («E=(-1,7)», «נקודה A ב-(0,0)», «E(-1,7)») and the rest of the analytic family (axes, slopes, line equations) are **refused** — nothing drawn, no paid call — with one message naming the analytic Builder's switcher button («גאומטריה אנליטית») and its spelling `E(-1,7)`. A message that sends the student to another tool names only a live tool, by its button, never a URL. A figure saved before the withdrawal still loads. **A foreign given is refused wherever it sits in the sentence**: a slope, quadrant, axes, coordinates, a plane or a solid is never committed as another given or dropped («כדור שמרכזו O» is not a circle) — the whole sentence is refused, quoting the student's word for it; the setting phrase «במישור …» is not refused.
  - Sources: ADR-AG-001, ADR-553, #1245, #1162, ADR-562, #1654–#1657, PR #1575.
- **FR-XP-1 (Should)** — **A crossing that IS a point the figure already has is refused, naming it.** When the two lines a student names share a letter — «D = חיתוך AB ו-BC», «D נקודת המפגש של AB עם BC» — their crossing IS that letter, whatever the configuration, and minting a second name for it gives one position two letters. The tool affirms the geometry and refuses the name, keeping the text and making no paid call. Points the student's own givens drive together keep their notice (FR-EN-20).
  - Sources: ADR-489 (naming half reversed), ADR-531, #1274, ADR-W-066, ADR-123.

## Refusals and honesty

- **FR-EN-8 (Must)** — Detect contradictory / unsatisfiable input (over-constraint), reject that step, keep the previous valid figure, and report why (US-3). The refusal **quotes the student's own sentence** as its subject, and the earlier statement it contradicts («X» סותר את «Y») when removing that one restores feasibility (else «סותר נתון קודם»). It blames the last statement whose addition made the figure infeasible — a later line that breaks an earlier given is itself named. A given that holds only in a degenerate limit, a polygon's angle sum past (n−2)·180°, or a bound and a value that cannot both hold is refused as a contradiction, never left pending; a flat declared polygon is FR-RN-13. Messages clear when the statement they are about is removed, muted or undone. A line whose operands are missing names the student's missing letters, never an internal id, and a cevian that names its triangle introduces it.
  - Sources: ADR-487, #943, ADR-492, #956, ADR-508, ADR-554, #1203, ADR-537, #1328, ADR-602, #1849, ADR-538, #1329, ADR-417, ADR-541, #1335, ADR-543, #1338, ADR-571, #1720.
- **FR-EN-23 (Must)** — **A stated side is a checked given: a statement that cannot coexist with it is refused.** «E מחוץ למעגל», «E בתוך המשולש ABC», «C ו-D בצדדים שונים של AB» are givens like any other. A statement placing the point where the side excludes (on the circle, at the centre, on a vertex or an edge, on the line it lies off, on the opposite side) is refused at the door, naming both statements in either order; a region's boundary belongs to neither side. A combination some figure can satisfy is never refused (a contradiction only a determined figure's coordinates show is the verifier's warning), and a satisfiable side holds in every configuration the tool offers.
  - e.g. «E מחוץ למעגל O» · «E על המעגל O» → «E על המעגל O» סותר את «E מחוץ למעגל O»
  - Sources: ADR-549, #1470, #1487, ADR-594, #1739.
- **FR-BND-1 (Should)** — **A bound admits its own boundary exactly when the student says so.** A measure bounded with **≥** or **≤** may be given exactly that value afterwards: «BC ≥ 10» then «BC = 10» builds, and BC is 10. Strict bounds (>, <, «גדול מ-», «קהה»/«חדה») exclude their value. A bounded measure stays free — no value reported, drawn visibly inside its region — until a given pins it, when the drawing preference gives way. Wordy forms («אורך הקטע BC גדול מ-10») bound like their bare twins, «לפחות»/«לכל היותר» are non-strict, and an excluded value is refused at the door naming both statements as written.
  - Sources: ADR-529, #1265, ADR-390, ADR-547, #1351, ADR-539, #1249, ADR-541, #1335.
- **FR-RN-13 (Must)** — **A declared polygon the givens force FLAT is refused, naming the statements.** When the stated givens collapse a declared polygon's vertices onto a line — «משולש ABC» with «AB = 5», «BC = 3» and «AC = 8», where the triangle inequality holds with equality; the same in any typing order, as a ratio, a sum or a perimeter; a quadrilateral whose sides do it; a stated collinearity or incidence that only a flat figure satisfies — the line that completes the collapse is **refused** before it becomes a fact, the prior figure kept, and the message names that line and the polygon's declaration («AC = 8» סותר את «משולש ABC») and says why: a flat line is not a triangle (or quadrilateral). A thin polygon that is still a polygon builds; a collapse only an unstated default forces yields to another configuration (M4).
  - Sources: ADR-W-115 (reversing ADR-W-048 for declared polygons), ADR-602, #1849, ADR-513 (notice net below the floor); 3-D twin [02b](02b-requirements-3d.md) FR-RD-7.
- **FR-IN-4f (Must) — a clause about points already on the figure is never dropped.** A sentence that says something about points the figure already has — «מעגל שקוטרו AB עובר דרך C» after «משולש ABC», «M אמצע AB ו-D על BC», «מעגל שמרכזו A עובר דרך B ו-D על BC» — either keeps that clause (it reaches the figure) or is not committed at all. A compound readable clause by clause builds whole; one that is not is escalated or refused. A position word 2-D does not read («B מתחת ל-AC») is likewise never committed green (operator ruling).
  - Sources: ADR-597, #1795, #1798.
- **FR-IN-4g (Must) — a one-line compound is all or nothing.** A student may write several givens on one line («AB=4, CD=3», «AB=u, AC=v, AS=w», «ריבוע ABCD, נקודה G על AD»), and when every clause is understood and honoured, the whole line commits. If any clause would be dropped or cannot be read, the whole line is refused with one message listing the student's clauses («בכל שורה נתון אחד — … נסו להקליד אותם בשני שלבים») — never a partial figure, never a paid call. Two clauses about one subject are one statement. **A part is "dropped" when the reading did not read it** ([ADR-603](06-decisions.md#adr-603), rulings 2026-10-08 on #1888/#1889): a vertex locative («משולש ABC ישר זווית ב-B»), a relative clause («…בנקודה E שהיא אמצע BD»), an incidence on a named point («…E על AB») — the line is refused whole, listing the parts cut where the reading stops («(1) AC ו-BD נפגשים בנקודה E  (2) שהיא אמצע BD»), **even when the drawing happens to satisfy the unread part**. «משולש ABC ישר זווית ב-<V>» is taught instead, as items (1) and (2) of that same list: «כתבו בשורות נפרדות: (1) משולש ABC  (2) ∠ABC = 90°», the angle named at the student's vertex, and any further part of the line continues the SAME list from (3) — **one numbered list from (1), however many parts the line has** ([ADR-611](06-decisions.md#adr-611), ruling 2026-10-09: *"Number the parts"*). The ✎ editor refuses the same edits, naming the unread part. An unread label inside a statement («AC ו-BD ו-AB נפגשים בנקודה E») goes to the AI fallback, as a dropped label always has. **A role word the reading did not read** ([ADR-604](06-decisions.md#adr-604), #1904) — «AD גובה לצלע BC שהוא גם תיכון» read as the median alone — refuses the line too, teaching one line per role: «כתבו כל תפקיד בשורה נפרדת: «AD גובה לצלע BC», ואחר כך «AD תיכון לצלע BC».»; a line an older gate already sends to the AI («…שהוא גם חוצה זווית») keeps going there.
  - e.g. «מרובע ABCD» · «AB מקביל ל-CD ו-D על BC» → refused whole
  - Sources: ADR-598, #1798, #553; 3-D and analytic parity #1842.
- **FR-IN-4h (Must) — a name's index is never a value.** A student may name a measure the book's way — «α1», «β2», «S1», «α_1», «Α1» (capital Greek) — and the tool never reads the index as the number: «∠ABC = α1» is not an angle of 1°. Such a line, a value the line cannot represent («∠ABC = α + 40», «∠ABC = π/3») and a comparison against one are **declined**, never drawn with a letter dropped. «שטח המשולש ABC = S1» is one statement.
  - Sources: ADR-600, #1814; analytic twin ADR-AG-244, #1785.
- **FR-EN-22 (Must)** — **A stated value whose subject is gone is a fact in error, never a silent no-op.** When the step that gave a letter its meaning («∠ABC = α», «AB = x», a radius symbol) is deleted, muted or edited away, the value row («α = 70», «x = 4») **stays in the list** (the tool never deletes the student's sentence for them), is **marked as not in effect** with a reason that names the letter, and the figure does not pretend the value applies. It takes effect again when a definition returns, and the action that orphaned it names the rows it left without effect. A bound or order on an unbound letter («0 < k < 6», «α < β») is likewise a waiting row; a bound follows a letter bound with a positive coefficient exactly («AB = 2k» · «k > 40» ⇒ |AB| > 80), and a form it cannot follow is refused by name.
  - Sources: ADR-W-044, ADR-483, #926, ADR-562, #1658.

## The figure and its marks

### Construction & engine

- **FR-EN-1 (Must)** — Build the figure incrementally: each new object may be defined in relation to objects already present.
- **FR-EN-2 (Must)** — Support free points; points constrained to lie on a segment, line, or circle; and derived points (intersection of two objects, midpoint of a segment, foot of a perpendicular).
- **FR-EN-3 (Must)** — Support shapes: triangle, quadrilateral, circle. Two circles can be stated **tangent to each other** at a point (external by default, internal on request). Sources: ADR-037.
- **FR-EN-4 (Must)** — Support constraints: distance, angle measure, right angle, parallel, perpendicular, equal segments. Also angle equality / ratio between two named angles (`∠ABC = ∠DEF`, `∠ABC = 2∠DEF`), driving a free DOF or checked on a determined figure. Sources: ADR-100.
- **FR-EN-5 (Must)** — Support special lines: height, median, angle bisector, perpendicular bisector, midsegment.
- **FR-EN-6 (Must)** — Compute positions for all objects that are consistent with the current facts.
- **FR-EN-7 (Must)** — Adding a new fact refines the existing figure; it must not reposition already-placed objects beyond what the new constraint requires (see [NFR stability](03-nonfunctional-requirements.md)).
- **FR-EN-9 (Must)** — Re-issuing an equivalent command is idempotent (no duplicate objects). A polygon is its ring: restated with its letters rotated or reversed («ריבוע ABCD» · «מרובע ADCB»), in a reading its word is symmetric under, it is the same no-op «כבר קיים» as in its declared spelling ([ADR-618](06-decisions.md#adr-618)); a crossing order is a different ring. A restatement in **another spelling** («AB ⟂ BC» after «∠ABC = 90») is the same no-op, «כבר קיים», judged by what the prior figure entails, never by command identity; one that also puts a value on the figure commits. Entailment ranges over the choices the tool made for unstated givens too (FR-HS-13, ADR-052): a restatement true only because of such a choice («AB ∥ DC» on «טרפז ABCD», «AC ⊥ BC» on «משולש ישר זווית ABC») is recorded as the student's statement, never «כבר קיים» ([ADR-605](06-decisions.md#adr-605)). Re-typing an **unticked** row's statement ticks it again; another spelling over its letters is refused, naming that row.
  - Sources: ADR-542, #999, #1007, ADR-578, #1748, ADR-010.
- **FR-EN-10 (Must)** — Recompute derived measures (lengths, angles, classifications) from final positions for display and theorem detection.
- **FR-EN-11 (Must)** — A constraint added on objects that are already placed *reshapes* the figure to satisfy it, rather than only checking it: the engine drives an available degree of freedom (an on-object parameter, a free point), and when the directly-referenced object has none, it recruits a free degree of freedom from an ancestor. Constraints compose; an unsatisfiable one is rejected per FR-EN-8. Sources: ADR-028.
- **FR-EN-12 (Should)** — A stated *relation between two triangles* — congruence (`ABC ≅ DEF`) or similarity (`ABC ~ DEF`) — reshapes the second triangle so the relation holds (congruent ⇒ corresponding sides equal; similar ⇒ corresponding angles equal), drawing either triangle first if it isn't already present. Two disjoint shapes are placed clear of each other. Sources: ADR-032.
- **FR-EN-13 (Must)** — Every shape carries the degrees of freedom of the real shape, so a sizing/shaping constraint *reshapes* it rather than being a spurious over-constraint: a square resizes from a side, a rectangle's height is settable, a rhombus's angle, a trapezoid's short side, a right-triangle's leg — while the shape's defining property (equal sides, right angles, parallels) is preserved. A constraint that cannot hold (a non-90° angle in a square) is still rejected per FR-EN-8. Sources: ADR-033.
- **FR-EN-14 (Should)** — A **cyclic quadrilateral** (`מרובע ABCD בר חסימה` / "cyclic quadrilateral ABCD" / "inscribable in a circle") — a common bagrut given — builds a convex quad whose four vertices are concyclic, so opposite angles sum to 180°, **without drawing the circumscribing circle** (a hidden circle that only constrains the vertices). «חסום במעגל» draws the circle. An inscription honours every shape adjective it states, in both directions; one it cannot draw is handed on, never dropped. «טרפז ישר זווית חסום במעגל» is refused naming both nouns. A ring already declared and then inscribed by its letters is drawn on its circle — except a ring declared a **right trapezoid**: «טרפז ישר זווית ABCD» with any inscription of ABCD («ABCD חסום במעגל», «מעגל חוסם את ABCD», «ABCD בר חסימה», the English forms), in **either order**, is refused at the second line, naming both statements and why (a circle through the four vertices makes it a rectangle) ([ADR-607](06-decisions.md#adr-607)). A circle inscribed in a ring named by its **letters alone** — «מעגל חסום ב-ABC», «מעגל חסום בתוך ABC», «המעגל החסום ב-ABCD», "circle inscribed in ABC" / "in ABCD" — draws the **inscribed** circle, tangent to every side, exactly the figure the noun spelling «מעגל חסום במשולש ABC» draws: three letters a triangle, four a quadrilateral, in both languages. Never the circle through the vertices ([ADR-609](06-decisions.md#adr-609)). The opposite direction, «ABC חסום במעגל», still draws the circle through the vertices. An n-gon of **five or more sides** inscribed in a circle builds deterministically, as the quadrilateral already does: «מחומש ABCDE חסום במעגל», «מחומש משוכלל ABCDE חסום במעגל», «משושה»/«מתומן», the `n-gon` forms and the English twins. The circle is **drawn**, every vertex rides it, and the vertex angles are a free DOF for a **plain** n-gon (unequal sides, re-sampled by «הציגו תצורה אחרת») and pinned for a **regular** one (equal sides at every configuration). «בר-חסימה» / "cyclic" states the same concyclic vertices and leaves the circle undrawn; a regular n-gon stated without an inscription keeps its circumscribing circle undrawn too ([ADR-610](06-decisions.md#adr-610)). A circle inscribed in a polygon of five or more sides («מעגל חסום במחומש ABCDE», lettered, unlettered, «מצולע», a bare run, either frame) is refused before any model is asked, with «הכלי עדיין לא יודע לשרטט מעגל חסום במחומש — זו מגבלה של הכלי.» (the noun filled in; seven or more sides: «…במצולע עם יותר משש צלעות…»); nothing is drawn ([ADR-606](06-decisions.md#adr-606), interim until #1908).
  - Sources: ADR-595, #1790, #1554.
- **FR-EN-15 (Should)** — Support **partial-circle shapes**: a **semicircle** (`חצי מעגל שקוטרו AB` / "semicircle with diameter AB") draws a 180° arc on a diameter (the diameter is drawn, the centre shown); a **quarter circle** (`רבע מעגל` / "quarter circle") draws a 90° arc with its two bounding radii. Only the arc and its straight edges render.
- **FR-EN-19 (Should)** — **Two circles intersecting at A and B.** "two circles intersect at A and B" / "שני מעגלים נחתכים בנקודות A ו-B" / "circles O and P meet at A and B" creates **both** circles (overlapping, default radius) and **both** intersection points A, B (the two branches) plus their common chord. (A single crossing of two *existing* circles is `G is the intersection of circle O and circle P`.)
- **FR-EN-17 (Should)** — **Secant from an external point.** "from a point E outside the circle, a line cuts the circle at A and B" / "מנקודה E מחוץ למעגל … חותך … בנקודות A ו-B" builds the two intersections A, B on the circle (a chord) and the external point E collinear with them (on the extension of the chord, outside the circle).
- **FR-EN-18 (Should)** — **From an external point: tangents (one or two) and multiple secants.** (a) **Two tangents** — "from point E outside circle O two tangents touch the circle at A and B" builds both tangent lines from E, touching at A, B (computed as `circle O ∩ circle-on-diameter-OE`, so EA⟂OA, EB⟂OB, |EA|=|EB|). (b) One tangent («ED משיק למעגל»). (c) Further secants from an existing E, which does not move. The Thales helper is hidden; a new E defaults to a standard external position.
- **FR-EN-21 (Should)** — **Secant from an apex, FAR point only.** "AD חותך למעגל" / "AD cuts the circle" (A the external apex, D the FAR-side crossing) builds a secant with only the far point named: D lands on the circle's far side, the near crossing is drawn as an anonymous promotable dot, and the secant's rotation about A is a free DOF (varies on "next configuration"). «…בנקודה B» names the near crossing; «…דרך P» pins the direction; «מנקודה A יוצא חותך למעגל בנקודה D» is read the same way. Sources: ADR-332.
- **FR-EN-20 (Should)** — **A forced coincidence is allowed, with a notice — not a hard error.** When the geometry or a stated relation genuinely drives two distinct points onto the same spot (e.g. a derived intersection landing on a circle's centre because a stated area/length ratio works out that way), the figure **still builds**; a notice tells the student the two labels converged. A genuine contradiction is still rejected (FR-EN-8), and by default the engine never stacks two nodes. Sources: ADR-123.
- **FR-EN-16 (Should)** — **Polygons are convex by default.** A declared polygon (quadrilateral, parallelogram, trapezoid, …) is always drawn convex unless the student explicitly asks for a **concave** shape (`קעור` / "concave"); "show another configuration" only surfaces convex configurations (a self-crossing or concave "dart" drawing is never offered unbidden — [ADR-018](06-decisions.md#adr-018), `polygonsConvex`). **No declared ring is ever drawn self-crossing**, whatever its noun: a ring the convexity default does not cover may be concave but never crossed — the inscribed «מתומן ABCDEFGH חסום במעגל» included, at every «הציגו תצורה אחרת» ([ADR-616](06-decisions.md#adr-616), #1968, operator ruling 2026-10-10). A stated `קעור` is a checked configuration branch. A polygon declared over points the figure has **already placed**, in an order whose sides cross in every configuration («ריבוע ABCD · מרובע ACBD», the pentagram «מחומש ACEBD» on a regular pentagon, or the ring first and the shape after it), is **refused, naming the line** that completes the crossing, with the shared ring message — never drawn folded, never a raw redefinition error ([ADR-608](06-decisions.md#adr-608), [ADR-W-121](06w-decisions-workspace.md#adr-w-121), #1927). A ring with a free vertex is a configuration choice, never this refusal. *Deferred:* a convexity preference in the constraint solver. Sources: #441.

### Rendering & interaction

- **FR-RN-1 (Must)** — Render points, segments, polygons, circles, angle arcs, right-angle marks, equal-side ticks (only in the opt-in relations layer, FR-RV-1 — never at rest), vertex labels, and dashed special lines. Sources: ADR-W-118 (B2), #1861.
- **FR-RN-2 (Must)** — **⚠ Ruled to change (2026-10-07, ADR-W-118 B9 · #1865):** a stated area is labelled «S=13» on the figure, as in every other tool, not «13». The text below describes the code until that ships. Constrained measures are labelled on the figure — a length along its segment, an angle at its vertex, the number or the expression (`3x`, `2α`, resolved once valued — FR-RN-12) — on by default, with one toggle. A measure the tool **refused** writes nothing on the figure. Sources: ADR-031, ADR-491, #955.
- **FR-RN-3 (Must)** — Animate position changes smoothly when a step moves existing points (no instantaneous teleport). (not built — 2026-10-07 audit)
- **FR-RN-4 (Must)** — Fit the figure to the viewport; provide pan, zoom, and reset.
- **FR-RN-7 (Must)** — Draw an angle mark at a vertex **only when the student stated that angle** (never from a merely computed 90°): a *right-angle square* for an explicit right angle (`∠ABC = 90`, a perpendicular `AB ⟂ CD`, a right-triangle), an *angle arc* for any other given angle (`∠ABC = α`, `∠ABC = 37`). Toggled with the measure labels. Sources: ADR-031.
- **FR-RN-8 (Should)** — **Show a circle's centre only when it is used or named.** A centre the student **named** (`circle O`, `circle centered at O`, `מעגל O`) is always drawn. An auto-assigned centre is hidden unless used. An unnamed centre **answers to no letter**: a new letter («BO = 5», «מעגל O») draws a new object until «O מרכז המעגל» places it; once two unnamed circles can be told apart, a new letter asks which. A name a line gives by use leaves with that line. A sentence putting a drawn point on a newly lettered circle names the drawn circle the point rides.
  - Sources: ADR-565, #1673, #1688, ADR-567, #1709, ADR-588, #1697, ADR-599, #1694.
- **FR-RN-12 (Should)** — **A parameter the student VALUED offers a display choice on the line that valued it; one they never valued is never replaced.** A bagrut question is worked in parts: part 1 reasons with «x» or «α», a later part supplies 4 or 70. The valuing row carries a chip that sends the figure back to the letter — per parameter, kept across configurations and save/load, only where both forms compete on a surface. A letter never valued stays on the canvas; its value stays in the data panel.
  - Sources: ADR-W-047, ADR-488, #948; 3-D counterpart [02b](02b-requirements-3d.md) FR-RD-6.
- **FR-RN-5 (Should)** — Allow dragging a point that has freedom: a **free** point anywhere, an **on-object** point along its host object (the drop projects onto the segment/circle/line). A drag is a soft reseed, not a pin; a drop the figure cannot solve returns the point (FR-EN-8); a derived point is not draggable. Sources: ADR-048.
- **FR-RN-6 (Should)** — Provide figure-orientation controls that change only the *view*, never the engine's geometry: rotate by 90° and 180°, flip horizontally and vertically, rotate freely, align a user-named segment to horizontal (type its two endpoints), and reset. Labels stay upright; align-to-horizontal is a standing request, re-applied on every change until reset.
- **FR-RN-9 (Could)** — **Position preview ("where can this point go?").** When the student selects a point to reposition, the canvas highlights a small set of **valid candidate positions** the point could occupy while every stated fact stays satisfied — the figure's residual freedom *for that one point*, made visible. About ten well-separated candidates; none for a derived point. The mechanism of FR-ALT-2 scoped to one point.
  - Sources: ADR-048, ADR-018, ADR-045.

### Letters and labels

- **FR-RN-10 (Should)** — **Edit a point's letter on the canvas.** Clicking a point opens a small menu to **rename** it (type a new letter — the same relabel as the typed `rename` command, [ADR-035](06-decisions.md#adr-035); refuses a letter already in use) or to **hide / show** it. A hidden point still participates and shows as a clickable ghost; hiding is a display preference. Clicking a segment offers hide / show, dashed / solid, and swapping its endpoint labels (FR-RN-11). Sources: ADR-072.
- **FR-RN-11 (Should)** — **Swap two existing labels (A ↔ B)** in one undoable step — the relabel that `rename` can't do (it refuses a taken target). From the segment menu or typed (`swap C and D`, `החלף בין C ל-D`); whole labels only (`C1` is never touched by `C`). Sources: ADR-122.
- **FR-RN-14 (Should)** — **A refused letter says who holds it.** When the student tries to name a point with a letter already in use, the refusal **names the statement holding it, quoted in their own wording, and highlights that step** — «האות כבר בשימוש» alone leaves them on the canvas with no way to find the holder. The tool then offers to swap the two letters, symmetrically; every statement and declared shape follows its letter, and one undo restores all. No path from the letter box ever deletes a statement.
  - Sources: ADR-520 (+ Am. 1), ADR-532, #238, #1013, #1199.
- **FR-RN-15 (Should)** — **A construction point off the drawn ink gets its line extended, dashed, to meet it.** When a point the construction puts on a line through two named points lands beyond the drawn piece (a height's foot past the end of its side, a crossing past its segments), that line is drawn on, dashed, from the end of the drawn ink out to the point. A point on the drawn piece gets nothing, and neither does a point the drawn ink already reaches. Recomputed per configuration.
  - Sources: ADR-612, ADR-W-124, #1971, #1937 (operator rulings 2026-10-09 and 2026-10-10).
- **FR-HS-7 (Should)** — **Relabel** a point everywhere (`rename E to G` / `שנה שם E ל-G`) so the lettering can match a textbook figure, without changing the geometry. Undoable; refuses a letter in use. See [12-letter-placement.md](12-letter-placement.md). Sources: ADR-035.
- **FR-HS-8 (Should)** — **Merge** two *existing* points into one (`merge F into E` / `מזג F ל-E`) — the explicit fold the rename deliberately refuses. The target survives, references are rewritten, collapsed facts removed; one undoable step. Refuses a shape vertex or a missing point.

**A letter run that encodes a ROLE is read from the figure, not from the typing order.** «רבע מעגל OAB» means
*centre O, ends A and B*; a run that does not build is re-read over the other role assignments and the one that
builds honestly (its radii equal, its angle 90°) is adopted, the step showing the spelling it used; else the step
refuses. The whole arc family («רבע מעגל», «גזרה», «חצי מעגל») reads a run the same way, a semicircle's centre
being the midpoint of its ends. **On three vertices of a shape**, «חצי מעגל ABC» passes through all three and the
figure picks the diameter (Thales), teaching «חצי מעגל שקוטרו AB העובר דרך C» (a stated diameter is honoured as stated); three loose points keep
the centre-first reading, with no possible diameter the step is refused, and «C על חצי המעגל» reads like «C על המעגל». Sources: ADR-521, #1012, ADR-534, #1204, ADR-589, #1771.

## Alternative configurations

- **FR-ALT-1 (Must)** — When a construction step has multiple valid solutions (e.g. the two intersections of a line and a circle), choose one deterministically and render it.
- **FR-ALT-2 (Must)** — Provide a control to **cycle to the next alternative configuration** when one exists; indicate when none does. It resamples the continuous free DOFs and advances discrete branches; the cyclic order of points on a circle is one such freedom unless the student stated it.
  - Sources: ADR-601, #1678.
- **FR-ALT-3 (Should)** — The chosen alternative persists across subsequent steps (cycling doesn't reset when a new fact is added).
- **FR-ALT-4 (Should)** — Show the figure's **remaining SHAPE degrees of freedom** as a running cue (`Degrees of freedom: N` while underdetermined; `✓ fully determined` at 0), so the student sees the freedom shrink as facts accumulate and stop when the figure's **shape** is pinned down. The fully determined state is visually emphasised. The count subtracts the constraint system's rank and the similarity gauge, so an implied constraint removes nothing; at 0 it says «נקבע במלואו» only for one configuration (FR-ALT-6).
  - Sources: ADR-018, ADR-101, ADR-536.
- **FR-ALT-5 (Must) — two named points never share a spot while another configuration exists.** Cycling with «הציגו תצורה אחרת», the automatic choice after a step, and the auto-resolver all **prefer a configuration in which no two named points land on each other**. A stacking configuration comes last, and when shown the two points are drawn as one label, «B=D».
  - Sources: ADR-486, #942, ADR-123.
- **FR-ALT-6 (Must) — zero degrees of freedom is not "one shape": the count says when another configuration exists.** A degrees-of-freedom count measures continuous freedom only; a figure can read 0 and still have more than one shape the givens allow — an unstated right-angle seat («משולש ישר זווית ABC · AB=3, BC=4»: the right angle at A or at B), an SSA triangle, a line–circle or circle–circle crossing choice. The cue then adds «יש N תצורות אפשריות» (N only when stable across seeds, else «יש יותר מתצורה אחת»), and says «נקבע במלואו» only for exactly one shape; no notice announces which choice was drawn. The check reads «בודק…» while running, is a fixed amount of work, never a time, and says so when the figure is too complex to check.
  - Sources: ADR-556, #1444, ADR-558, #1599, #1601.
- **FR-ALT-7 (Must) — a side named by its role follows the configuration.** A line drawn to a side named by its ROLE — «תיכון לבסיס», «גובה לבסיס», «גובה לשוק», «תיכון ליתר», "median to the base" — stays on THAT role's side in every configuration «הציגו תצורה אחרת» shows: when the button moves the isosceles apex, the median to the base is redrawn from the new apex to the new base, and two altitudes to the legs stay on the two legs, never the base. A later statement that settles the choice moves it too; letters typed are kept as typed.
  - Sources: ADR-596, #1810.
- **FR-HS-12 (Must) — the same input gives the same figure: a structural edit resets the configuration.** The source of truth is the pair **`(facts, seed)`**, not the fact list alone: the ordered facts say WHAT the figure is, and the sampling `seed` says WHICH of its valid configurations is being shown (it is saved in the file, FR-HS-10, and it is what "הציגו תצורה אחרת" cycles). Deleting, editing or turning off a step resets the seed; undo, load and relabel do not. A configuration the tool cannot draw is never shown.
  - Sources: ADR-484, #938.
- **FR-HS-13 (Should) — a choice the tool makes for an UNSTATED given is SAID, for as long as it is unstated.** The honesty invariant's communication half. Where the tool must choose to draw at all (an isosceles apex, a kite's axis, an isosceles trapezoid's parallel pair), the step row says what is drawn, the sentence that would state it, and that «הציגו תצורה אחרת» cycles it — as a sentence typable as the next line, until the student states it (and again if that statement is turned off). A trapezoid's assumed pair follows the noun and letters (AB ∥ DC for «טרפז ABCD»); a stated pair re-seats it.
  - Sources: ADR-138, ADR-506, ADR-502, #973, #996.
- **FR-TH-6a (Should)** — **⚠ Ruled to change (2026-10-07, ADR-W-118 B11 · #1866):** the «נשמר: הענף של E» wording is reworded in a student's words; the new text is the operator's to approve. The text below describes the code until that ships. When «show another configuration» changes the drawing, the tool says which unstated choice it moved and which it kept («השתנה: המיקום של G · נשמר: הענף של E»), naming only freedoms the figure has, capped like every surfacing (FR-TH-6).
  - Sources: ADR-052, ADR-517, #65.

## Knowledge — relations, values, theorems

### Reveal — the ground-truth relations layer ("view relations") — BUILT

On-demand, **opt-in** annotation of what the figure geometrically *is* — the **ground truths** the givens force; it serves exploration and must **never** clue the student unbidden. Sources: ADR-134, ADR-W-041, #904.

- **FR-RV-1 (Should)** — Provide a **"view relations"** control that, only when the student presses it, annotates the current figure with the ground-truth relations it exhibits: **equal segments** (tick marks — one tick-class per equality group), **equal angles** (arc marks), **right angles** (square), and **definitive measured values** (FR-RV-5). It is hover-driven (a resting figure stays clean) and shows stated and derived relations alike. Sources: #444, ADR-167 (amendment 2), #1861.
- **FR-RV-2 (Should)** — Reveal is **strictly opt-in and reversible**: nothing is annotated until requested. A button (not a toggle) running a short analysis (~2–3 s), dismissible, auto-cleared by a new fact (Pedagogy §5.1).
- **FR-RV-3 (Should)** — Reveal is powered by **coordinate analysis across MANY sampled configurations** (the free-DOF sampler of FR-ALT-2), not a single drawing. A relation is shown only if it holds in every sample. Sources: ADR-038.
- **FR-RV-4 (Should)** — **Similar / congruent triangles** are shown in a **list beside the canvas, not drawn on the figure** (keeps the diagram uncluttered). Each entry gives the vertex correspondence and highlights its two triangles; drawn-segment triangles only (FR-RV-6).
- **FR-RV-5 (Should)** — **Values and area relations are shown only when DEFINITIVE** — the same across every sample. Angles and ratios whenever forced; absolute lengths and areas only when the figure is scale-anchored. The check is a fixed amount of work, never time, says so when a figure is too complex, and answers a later question from the same check («מחשב…» while running).
  - Sources: ADR-101, ADR-558, #1601, ADR-582, #1605.
- **FR-RV-7 (Should) — a letter the student named is a QUANTITY.** When a student writes «AB = 3x», «AC = x» or «∠ABC = α», the letter is not merely notation the figure is expressed in: it is a **thing with a value**, and the values panel prints it — «x = 2.77» — the moment the figure determines it, alongside the lengths and angles it derives. It is askable by name and obeys every row's discipline (a length letter needs the scale pinned); a letter valued outright is a **נתון**, and a letter the figure never mentions is not recognised.
  - Sources: ADR-485, #929; 3-D since ADR-3D-219.
- **FR-RV-8 (Should) — a values-panel row names only what the student can see.** A row's label names an object by what the student typed or the figure shows: a circle whose centre is a visible point is «רדיוס O»; an unnamed circle is «רדיוס המעגל» when it is the only one, and «רדיוס מעגל O» — the letter «מעגל O» already refers to, and «הצג מרכזים» draws — beside other circles. A circle the tool never draws has no row, and no row shows an internal id. Sources: ADR-552, #1442.
- **FR-RV-6 (Should)** — **Object universe is bounded for runtime.** Only objects that **actually appear** are tested — but "appear" means **visibly on the page, not only declared** ([ADR-162](06-decisions.md#adr-162)): the universe is drawn segments + polygon edges **plus implicit edges** — on-host splits (a point on a segment connects to that segment's endpoints, so the two halves of a diameter `OA`/`OB` are tested) and points sharing a drawn line. Pairwise over that universe with a capped sample count; the layer doubles as an audit of ADR-052.

### Theorems

**Status:** the theorem surface is switched off by the operator (#740: *"not ready and just confusing"*). The engine (`src/theorems/`) and its tests stay live; re-enabling the surface is the operator's decision ([ADR-W-118](06w-decisions-workspace.md#adr-w-118) B4).

- **FR-TH-1 (Must)** — When a fact is entered, run detection over the **entire accumulated figure** (all enabled facts), and surface what has **changed**: theorems whose hypothesis is now satisfied, and confidence/relevance updates to theorems already shown. A fact may legitimately surface nothing.
- **FR-TH-2 (Must)** — Surfaced theorems accumulate in a **growing feed** alongside the canvas. Each entry is attributed to the fact that completed it, drops with that fact, and updates in place rather than duplicating.
- **FR-TH-3 (Must)** — Each entry carries a **confidence tier**, **recomputed every step** as the figure grows (a *possible* match becomes *certain* when its completing fact arrives, and can drop again if that fact is removed), driving both ordering and visual treatment, highest first:
  - **Certain** — the hypothesis is fully met by the construction (green). *e.g. a diameter is present → Theorem 103.*
  - **Possible** — would hold only in a more special case, one given away (amber). *e.g. two equal sides given → isosceles is **certain**, equilateral is **possible**.*

  The tier is ordinal, never a score or a percentage (Pedagogy §5.4).
  - Sources: ADR-038; `src/theorems/types.ts` `Tier`; [docs/18](archive/18-theorem-relevance-plan.md) D3; #1861.
- **FR-TH-4 (Must)** — Each feed entry is **traceable**: selecting it highlights on the canvas the exact objects/facts that satisfied the hypothesis (Pedagogy §5.3).
- **FR-TH-5 (Must)** — Present each theorem bilingually (He/En) with its exact catalog statement ([07](07-theorem-reference.md)) and its **official bagrut number**. Surface **P** (use-it) and **C** (recognition/converse) theorems; **never** surface **O**-tagged items, definitions, or area/perimeter formulas.
- **FR-TH-6 (Should)** — Within a single fact's surfacing, order most-relevant-first and **cap** the count so one fact never floods the feed.

### Shape badges — detect named shapes and link to the book ([ADR-161](06-decisions.md#adr-161))

Not the theorem layer: it answers "which named shapes does this figure contain, and where do I read about them." It is the built realization of the **FR-REF-1** shape-link idea for the *shape* surface (theorem links remain Later).

- **FR-SH-1 (Should)** — Provide a **"detect shapes"** control that, only when the student presses it, classifies every polygon/circle the figure contains into a **named shape** (square, rectangle, rhombus, parallelogram, kite, trapezoid / isosceles- / right-trapezoid, triangle / isosceles- / equilateral- / right-triangle, circle) and lists each as a **badge** (localized name + vertex label). A new fact clears the layer.
- **FR-SH-2 (Should)** — Detection is **geometric and forced**: a type is reported only if its defining properties hold in **every sampled configuration** (the free-DOF sampler of FR-ALT-2 / FR-RV-3), so an **emergent** shape — a general quad that accumulated constraints have pinned into a kite — is detected, while a shape that holds only in the current drawing is **not** reported. Most-specific type, over the implicit edge universe, where an emergent cycle badges only as a named special type. Sources: ADR-162.
- **FR-SH-3 (Should)** — A badge is **traceable to the figure and to the book**: **hovering** a badge highlights its shape on the canvas (vertices + drawn edges — reusing the FR-EN selection highlight), and **clicking** it opens a small **inline card** (not a figure-hiding modal, so the highlighted shape stays visible) with the shape's name, a one-line definition, and a prominent **link to that shape's page in the geometry book** on the same site (`themathbible.com/bagrut/5-yehidot/571/geometry/<slug>`), opening in a new tab. The `ShapeType → slug` map is a single source of truth versioned with the app.

### Textbook references — link out to the geometry book (deferred)

- **FR-REF-1 (Later)** — **Deep-link a detected shape or theorem to its page in the geometry book.** When the figure contains a recognised shape (kite, square, rhombus, parallelogram, trapezoid, isosceles/equilateral triangle, circle, …) or surfaces a theorem (FR-TH), offer an **unobtrusive link** to the corresponding page/anchor in the geometry book on the same site, so a student who wants the definition, properties, and theorems for that object can read them in context. A reference, never a clue to the solution; opt-in and quiet. Open items: the URL map, the trigger surface, graceful absence. The shape surface is built (FR-SH); theorem links remain Later. Sources: [pedagogy charter](10-pedagogy.md).

Generalised as [02w](02w-requirements-workspace.md) FR-SL-7.)*
- **FR-HS-10 (Should) — save a figure to a file and load it back.** Offer an explicit **download** of the current construction as a small **text file** and an **upload** that restores it, so a teacher or student can keep a figure and reopen it later without rebuilding it (US-14). The file holds the facts, `seed` and styling, never positions; load replays as one undoable step, refuses bad or newer files, re-lowers deterministic steps against today's parser (LLM steps kept), and loads a save exactly as saved. Saving a named figure asks overwrite or copy. A built-in library of figures remains future.
  - Sources: ADR-232, ADR-314, #120, ADR-579, #1604, ADR-315, #121.

Deterministic, no LLM; `question-YYYY-MM-DD.docx`, disabled with no enabled utterance. Sources: ADR-251.
- **FR-HS-9 (Could — planned, flag-gated, premium)** — **Export a textbook-style problem statement.** Alongside the image export (FR-HS-5) and the construction copy, offer a third output: a **natural-language description of the figure's *givens*** in the register a printed textbook/exam would use — e.g. *"ABCD טרפז החסום במעגל. …"* — not a transcript of the steps.
