feat(parser): bare free point «נקודה A» positioned by the next statement (#104)

Root cause: "free point (2 DOF)" was a core primitive of the original model that
the rebuild never re-exposed — every point arrived via a relation. A bare
`נקודה A` / `point A` had no parser rule AND was intercepted by a `bare-point`
scope classifier ("say where it sits"), so it never built. ~4 prod users hit it.

Fix (ADR-328):
- new `bareFreePoint` rule: He `נקודה X`/`הוסף נקודה X` (+ optional ה), En
  `point X`/`add point X` → `free-point{free:true, ifAbsent:true}` (ADR-052
  sampled DOF; idempotent, M1 no-op on re-declare). Anchored end-to-end so a
  trailing relation (`נקודה A על AB`) still goes to the relational rules; a lone
  letter (`C`) keeps its guidance.
- narrow the `bare-point` scope classifier to the lone-letter / line-carries-a-
  point forms only (the keyword forms now build, not brushed off).
- regionSideFallback: recognise a bare point-reference head BEFORE the full-
  statement path, so `נקודה E בתוך משולש ABC` names the region subject instead of
  the new rule turning it into a standalone free point (double-declare).
- catalog entry `point A` / `נקודה A`; snapshots + scope test updated.

bare-free-point.test.ts + scenario bare-free-point-positioned-by-next-statement
(`נקודה A` + `נקודה B` + `AB=5` → |AB|=5). Full 2-D lane green (3449), tsc + build clean.

Closes #104
