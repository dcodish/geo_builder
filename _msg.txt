feat(parser): a semicircle on EVERY side of a polygon (#29)

Root cause: the classic bagrut composite (a polygon with a 180° arc erected on
every side) was not-handled — only the single-side form («על צלע CD יש חצי מעגל»,
already closed-form since #28) parsed; the quantified «על כל צלע של ריבוע יש חצי
מעגל» fell through (the surviving כל/ריבוע tripped SHAPE_LEFTOVER → escalate, #27).

Fix (ADR-330, ADR-110 macro — no new engine construct): a `semicirclesOnEverySide`
rule (before `semicircle`) gated on a semicircle keyword AND the כל צלע/every side
/each side quantifier. Resolves the polygon (a named «ריבוע ABCD» run, else the
figure's single polygon) and emits one closed-form semicircle per side. A named-new
polygon is built inline first (self-contained «…ריבוע ABCD…», basic shapes only);
a partial/ambiguous polygon defers (ADR-052). Label runs are UPPERCASE-only so
English prose ("square THERE is …") is never mistaken for vertices.

Known limitation (documented): the bulge SIDE (outward/inward) is winding-dependent
and unknowable at parse time (no coordinates) — v1 uses a consistent arc convention;
per-side outward orientation is a follow-up.

Updated issue-27 (the #27 half-parse guard) to assert the quantified form now BUILDS
one semicircle per side (the honest outcome). semicircle-every-side.test.ts + scenario
semicircle-on-every-side-of-square (4 arcs). Catalog +1; snapshots updated.
Full 2-D lane green (3448), tsc + build clean.

Closes #29
